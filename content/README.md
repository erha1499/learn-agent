# Agent 学习手册：基础、工程、评测和面试

## 导读：Agent 是给一个不可靠的零件，配上可靠的工程

大模型会写、会推理，但它按概率续写：每次结果可能不同，写出来的东西不保证是真的，还要花钱、花时间。它也碰不到外面的世界：查不了数据库，改不了文件。

**Agent** 是让模型在一个循环里反复“说要做什么 → 程序去做 → 把结果给它看”，直到把任务做完的系统。模型负责判断，循环、工具、权限、上下文这些模型以外的部分叫 **harness**。**Agent 工程**做的是把 harness 搭好，让这个不可靠的零件在里面可靠地干活；**Agent 评测**做的是在上线之前和之后，用数据回答“它到底好不好、有没有变好、能不能信”。

全书用一个贯穿的小例子：**迷你值班现场**（`examples/mini_world.py`）。几台出了问题的 MySQL 实例，几个查询工具，一个排查故障的值班 Agent，从单元二的一次工具调用，一路长到单元十二的断点恢复；评测部分在它上面造了一套 20 条用例的评测集（`examples/mini_eval.py`）。它只是一个例子，不依赖任何外部项目；书里的每个数字都来自仓库里能直接运行的代码，录下的真实输出在 `examples/output/`，没有 key 也能看。值班排障只是场景，讲的机制对客服、编程、调研类的 Agent 同样适用。

全书还反复拿三个现成的东西做参照：**Claude Code**（Anthropic 的命令行编程 Agent，功能最全的 harness 之一）、**pi**（一个开源的极简编程 Agent，故意只做最少的功能，源码适合对照着读）、**learn-claude-code**（一个开源教程，从一个循环开始，一章加一个机制，一步步搭出 Claude Code 的主要结构）。

### 读者

五个部分的起点不同，每部分开头写了它面向谁、要先会什么。全书的共同起点是：会 Python，调过大模型的 API。统计（置信区间、配对比较、样本量）只在用到时交代，不推公式；具体框架和 SDK 的 API 也只在用到时交代。

| 你现在 | 从哪读 |
|---|---|
| 只会调大模型，不清楚 Agent 和 harness 是什么 | 第一部分，按顺序 |
| 用框架搭过 Agent，想知道每个机制为什么这么设计 | 第二部分；概念卡住时回查第一部分 |
| 手上有 Agent，要回答“它好不好、改了有没有变好” | 第三部分；先看单元一和单元三 |
| 要把 Agent 交给真实用户 | 第四部分 |
| 准备面试 | 第一部分 → 单元十三 → 第五部分；其余单元先看「面试常问」，答不上来再读正文 |

### 第一部分 Agent 基础

写给会调大模型 API、但不清楚 Agent 和 harness 是什么的人，会 Python、调过一次聊天接口就能读。从一次模型调用出发，一步步长出一个 Agent：工具调用、循环、harness，最后拆开一个真实的 Coding Agent。读完能自己写出一个最小 Agent，讲清 Claude Code 这样的 harness 由哪些部分组成、各自解决什么问题。

| 单元 | 一句话核心 |
|---|---|
| [一 大模型：一个按概率续写文字的零件](01-llm-basics.md) | 每次调用都花钱花时间，同样的输入不保证同样的输出，写出来的不保证是真的 |
| [二 工具调用：模型只说要调什么，做事的是你的代码](02-tool-calling.md) | 模型只会输出“想调哪个函数、参数是什么”；执行、校验、把结果送回去，全是你的代码 |
| [三 Agent 循环：把工具调用放进一个 while](03-agent-loop.md) | 模型要工具就执行、结果追加回去、再问一次，直到它不再要工具；什么时候停、停下来交了什么，要你兜底 |
| [四 Harness：Agent = 模型 + Harness](04-harness.md) | 模型管判断，harness 管其余一切；机制挂在循环的固定位置上，管边界和验收，不替模型做决定 |
| [五 解剖一个 Coding Agent：从三十行循环到 Claude Code](05-coding-agent.md) | 编程 Agent 就是循环加 harness，再为长任务加上文件工具、计划、子 Agent、技能、压缩、记忆；每样都解决一个问题，也都有代价 |

### 第二部分 Agent 工程

写给读完第一部分、或者已经用框架搭过 Agent 的人。每个单元讲一类机制：为什么需要、怎么做、代价是什么、什么时候不该用。读完能为自己的场景选对机制，并说清取舍。

| 单元 | 一句话核心 |
|---|---|
| [六 调用工程：结构化输出和提示词](06-calling-engineering.md) | 输出先过程序校验，格式尽量交给接口约束；提示词当代码管；会变的放最后，缓存才省钱 |
| [七 工具设计和协议：MCP、A2A、Skills](07-tools-and-protocols.md) | 报错要给模型指路，工具要按需出现，外来的描述和返回值都不可信；协议解决复用，不解决可靠和安全 |
| [八 编排和多 Agent](08-orchestration.md) | 多 Agent 买来并行和隔离，代价是调用更多、彼此看不到对方知道什么；要拆就把完整上下文传下去，并有人验收 |
| [九 上下文工程和记忆](09-context-and-memory.md) | 输入的大头是工具输出；长会话要结构化压缩而不是截断，截断后模型会编；记忆只记查不到的，用前要核实 |
| [十 RAG 和 Agentic RAG](10-rag.md) | 检索决定上限；经典 RAG 便宜可控，Agentic RAG 能补上一次检索漏掉的，代价是几倍的调用；检索和生成分开评 |
| [十一 安全：注入、越权、沙箱](11-security.md) | 模型分不清指令和数据，防注入靠“被骗了也做不成坏事”：真实身份校验、危险动作拦截、隔离、砍掉往外发的那条腿 |
| [十二 走向生产：状态、并发、网关、可观测、框架选型](12-production.md) | 事件日志恢复加业务身份做幂等，网关管超时重试和预算，一次运行一条轨迹；事件日志一份记录三处用 |

### 第三部分 Agent 评测

写给手上有一个 Agent、要回答“它到底好不好”的人。已经会写 Agent 的可以从这里直接开始，需要的前置只有单元一讲的输出随机性和单元三的循环。读完能设计评测集和打分器、跑实验、判断一个结论能不能信。

| 单元 | 一句话核心 |
|---|---|
| [十三 Agent 为什么难评：一次成功只是一次抽样](13-why-eval-is-hard.md) | 评的是一批任务上多大比例能稳定做对、做对的方式靠不靠得住、花了多少代价 |
| [十四 评测集：从哪来、写什么、要多大](14-eval-sets.md) | 评测集决定你能看见什么：来源要混合，标准要能判，规模要够看出你关心的差距；要校准难度、分组、版本化，并从线上失败补新题 |
| [十五 指标和打分器：分数是打分器给的](15-graders-and-metrics.md) | 同一批运行换个打分器，分数就变；判最终状态不判说法，能用代码判的用代码判；几个分数怎么合成一个要按场景定，打分器本身也要测 |
| [十六 让大模型当评委：先校准，再相信](16-llm-judge.md) | 评委本身也是一个要评测的模型：偏爱写得长的、排在后面的，看不到证据就判不出编造，细则含糊两个评委就各判各的；拆成是非题、给证据、换顺序，上线前和人工核对的样本算一致率 |
| [十七 结论能不能信：噪声、置信区间、配对比较](17-noise-and-confidence.md) | 分数是一次估计：区间按用例算，比较在同一批用例上配对；“这批用例上是不是运气”多跑几遍就能回答，“换一批用例还成立吗”只能靠加用例；看什么、比什么，跑之前写下来 |
| [十八 公开基准和红队：先读脚注，再找漏洞](18-benchmarks-and-red-teaming.md) | 榜单数字是模型加 harness 加配置的结果，题会错、会泄露、会被做穿，只用来圈候选；红队不量比例而是找漏洞，攻击者弱就是走过场，找到的攻击进回归集，修复要靠程序层 |
| [十九 线上评测和评测平台：没有标准答案的时候](19-online-eval.md) | 上线后答错了没人告诉你：几层不用标准答案的信号叠着用，每层都有洞；找错看被标记的，估水平要随机抽；过程指标做告警，质量按类型配对比；平台把轨迹、打分、比较、复核和门禁串起来 |

### 第四部分 做一个能上线的 Agent

写给要把 Agent 交给真实用户的人。默认你有后端工程的基本经验（部署、日志、CI），只讲和 Agent 有关的部分：从立项定标准，到上线后持续观察和改进。

| 单元 | 一句话核心 |
|---|---|
| [二十 立项：先定标准再写代码](20-kickoff.md) | 先量最简单的方案，它做不到的才是 Agent 要挣的钱；答错和不答的代价比决定要不要留“不知道”的出口、程序的门设多严；标准写成带门槛的记分卡，权限先窄后宽 |
| [二十一 搭骨架：配置、存储、队列、网关、轨迹](21-skeleton.md) | 会改变输出的配置算指纹；事件日志只追加，恢复、轨迹、导出评测题都从它读；任务进队列、用租约，worker 数对齐上游限额，重试只在网关；轨迹用标准名字、默认不带正文 |
| [二十二 上线：发布物、门禁、灰度、回滚](22-shipping.md) | 提示词、工具描述、模型快照都会改变行为：发布物是钉死的指纹加快照，任何改动走同一道门禁（底线、回归题、配对比较）；灰度两个版本同时比、先看过程指标；回滚就是改指针 |

### 怎么用这份手册

每个单元按同一个节奏组织：

1. **先看现象，再学原理**：能用代码复现的，先给可运行的代码和真实结果，再解释为什么。标着「深入一层（可跳过）」的部分第一遍可以跳过。
2. **动手**：例子在仓库的 `examples/`，文件名前缀是单元号。调模型的例子会把真实输出录在 `examples/output/`，加 `--replay` 不调模型直接看；只做统计的例子直接跑，不花钱。
3. **带走**：每个单元末尾的「做项目时」是一张清单，做自己的项目时逐条对照。
4. **检验**：「面试常问」是原理的口述压缩版，读懂原理后再看。里面的“我实测”是示范说法，数字来自本书的实验，面试时换成你自己跑出来的数字和自己的项目。最后合上文档做自测题，答案在 `answers.json`。

文中的模型行为都在 qwen-plus 上实测（2026-11）。框架、基准、价格变化很快，涉及时效的地方注明了日期，以官方文档为准。Agent 的很多做法还没有定论，书里引用的厂商工程文章（以 Anthropic 为主）都注明了日期和模型，读的时候把它们当作某个时间点上的一种做法；单元二十六把这些文章按时间列在了一起。
